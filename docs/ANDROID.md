# Приложение для Android: подпись

APK собирает задача `android` в `.github/workflows/pages.yml`. Gradle собирает его без подписи, подписывает отдельный шаг «Подпись APK» ключами из секретов GitHub. В репозитории ключей нет и быть не должно (`android/.gitignore`).

## Ключи

| Ключ | Псевдоним | SHA-256 сертификата |
|---|---|---|
| старый (до 2.123.0) | `eslacity` | `D2:42:AB:5B:C4:C1:7C:D5:D4:65:B1:33:D9:6E:98:0C:E5:FD:25:FA:79:D2:01:35:6E:CF:F6:8C:4B:AF:AC:7C` |
| новый (с 2.123.0) | `eslacity2026` | `4E:B8:A5:55:CB:CB:9E:38:FF:DD:4B:F4:D0:18:4D:55:0A:0B:75:E9:2C:EC:C3:CF:8E:5E:46:6A:D5:65:BB:7F` |

Старый ключ лежал в открытом репозитории, поэтому его сменили. Android принимает обновление, только если оно подписано тем же ключом, что и установленное приложение, или ключом, которому тот доверяет. Доверие задаёт цепочка (lineage) APK Signature Scheme v3: старый ключ подписывает новый, цепочка лежит внутри APK. Так обновление с новым ключом встаёт поверх версии со старым, прогресс остаётся.

Цепочка в v3 работает с Android 9, поэтому с 2.123.0 у приложения `minSdkVersion = 28`. На Android 7 и 8 остаётся установленная версия, игра в браузере работает везде.

## Секреты GitHub

Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Что в нём |
|---|---|
| `ANDROID_KEYSTORE_B64` | новый ключ (PKCS12) в base64 |
| `ANDROID_KEYSTORE_PASSWORD` | пароль нового ключа (хранилища и ключа одинаковые) |
| `ANDROID_OLD_KEYSTORE_B64` | старый ключ (PKCS12) в base64 |
| `ANDROID_OLD_KEYSTORE_PASSWORD` | пароль старого ключа |

Base64 файла: `base64 -w0 eslacity-2026.p12`. Если секрета нет, шаг подписи падает с сообщением, какого.

Оба ключа нужны всегда: старым подписаны схемы v1 и v2 и звено цепочки, новым — схема v3. Потеря любого означает, что обновление поверх уже не встанет: храните копии ключей и паролей вне GitHub (менеджер паролей, второй носитель).

## Что делает CI

1. `apksigner rotate` строит цепочку старый → новый.
2. `zipalign` выравнивает APK.
3. `apksigner sign` со старым ключом, `--next-signer` с новым, `--lineage` и `--rotation-min-sdk-version 28`.
4. `apksigner verify --print-certs`: подпись v3 верна, сертификат — новый ключ.
5. `apksigner lineage --print-certs`: в цепочке оба ключа.

Если отпечатки не совпали, задача падает и APK на сайт не попадает.

## Проверить у себя

```bash
apksigner verify --verbose --print-certs eslacity.apk
apksigner lineage --in eslacity.apk --print-certs
```

## История git

Старый ключ остался в истории репозитория. Убирать его оттуда (`git filter-repo` и принудительный push) — решение владельца: это переписывает историю у всех клонов, а сам ключ всё равно уже был открыт. Главное сделано сменой ключа: сборку от имени Eslacity теперь подписывает только новый ключ.
