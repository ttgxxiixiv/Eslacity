# Вычитка контента носителем

Весь текст игры на изучаемом языке можно выгрузить в таблицы, отдать носителю, а его правки потом загрузить обратно (задачи 11.2 и 11.3).

## Выгрузка

```bash
npm run review:export                         # оба языка, все виды → review/<язык>/<вид>.csv
npx tsx scripts/export-review.ts it sphinx    # только итальянский Сфинкс
npx tsx scripts/export-review.ts --out ~/out  # в другую папку
```

Папка `review/` в git не попадает.

Виды (файл на каждый):
- `words` — слова мест, свитков и праздников с примерами;
- `phrases`;
- `scenes`;
- `missions`;
- `grammar` — упражнения, примеры, испанские и итальянские примеры из теории и пояснений;
- `sphinx`;
- `letters`;
- `people` — реплики жителей, стражей и Летописца;
- `verbs` — неправильные формы кузницы;
- `pairs` — Звонница.

В каждой таблице строки идут от сложного к простому. Сверху стоят C1 и глава V: выражения, Сфинкс, письма. На этом уровне неестественность заметнее всего, их стоит отдать первыми.

## Что делает носитель

Таблица открывается в Excel, LibreOffice или Google Таблицах (UTF-8, разделитель — запятая).

| Колонка | Что это |
|---|---|
| `file`, `path` | адрес строки в контенте, **не менять** |
| `id`, `level` | где это в игре и какого уровня |
| `ru` | что строка должна значить по-русски |
| `text` | как сейчас, **не менять** |
| `fix` | правильный вариант, если текущий неверен или звучит неестественно; пусто — всё хорошо |
| `comment` | пояснение, если нужно |

Строки с `___` — пропуски в упражнениях, их оставляют на месте. Слова в скобках во фразах — необязательные. Если правка меняет ответ упражнения, стоит проверить и варианты рядом: у упражнения несколько строк подряд с одним `id`.

## Загрузка правок

```bash
npm run review:import -- review/es/sphinx.csv review/es/words.csv   # язык — из папки
npm run review:import -- --lang it ~/Downloads/правки.csv            # файл из другой папки
npm run review:import -- review/es/*.csv --dry-run                  # только отчёт, файлы не меняются
```

Как работает загрузка:
- Применяются строки с заполненным `fix`. Скрипт находит строку по `file` и `path` и заменяет в файле только её. Остальной файл и его форматирование не меняются, так что в диффе видно ровно правки.
- Если в контенте уже другой текст, чем в колонке `text`, правка пропускается: пока таблица была у носителя, строку успели поменять. Правка, совпадающая с текстом, и адрес, которого нет, тоже пропускаются.
- Таблицу можно сохранить и с `;` вместо `,`, как это делает русский Excel.
- Отчёт — `review/<язык>/applied-<время>.md`: что было, что стало, комментарий носителя, пропущенное и почему.
- После правок запускаются валидатор и тесты контента (`src/content`, `scripts`). Ошибка или предупреждение — повод посмотреть вывод. Частый случай: в примере слова нет нового слова или правка ответа сломала варианты упражнения. Поправьте вручную или откатите: `git checkout src/content`.

Short note in English: fill only the `fix` column (and `comment` if needed); keep `file`, `path` and `text` as they are.
