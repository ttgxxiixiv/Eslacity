# Дорожная карта Eslacity

Пошаговый план развития для работы через Claude Code. Концепция, из которой он вырос: восемь этапов от тренажёра слов к обучающей RPG с жителями, квестами и прогрессом, который измеряет умение, а не потраченное время. Здесь каждый этап разбит на задачи, которые делаются по одной за сессию.

Правила проекта, команды и порядок выпуска версии описаны в `CLAUDE.md`, Claude Code читает его сам.

## Как работать по этому плану

1. Одна задача — одна сессия Claude Code и одна версия приложения. Большие задачи уже разбиты на части; если задача всё равно не помещается, Claude сам предложит, где её разрезать.
2. Скопируйте в сессию запрос из блока «Запрос» у нужной задачи. Запросы короткие: подробности Claude прочитает в этом файле.
3. Идите по порядку внутри этапа. Зависимости между задачами указаны в строке «Нужно до».
4. После выпуска отметьте задачу `[x]` в оглавлении и добавьте строку в журнал в конце файла. Это можно поручить Claude в том же запросе, он уже есть в шаблоне.
5. Если по ходу решение изменилось (например, выбран другой формат данных), Claude правит описание следующих задач здесь же, чтобы план не расходился с кодом.

### Определение готовности (для каждой задачи)

- Логика в `src/domain/` покрыта тестами, `npm test` проходит.
- `npm run build` проходит: валидатор контента, типы, сборка.
- Сценарий задачи пройден в браузере на обоих языках (после 0.2 — через `npm run e2e`).
- Прогресс со старой версии открывается без потерь. Если менялась база, есть тест на перенос данных.
- Версия поднята, есть запись в `src/content/changelog.ts` и раздел в `docs/STAGES.md`.
- Изменения отправлены в ветку `claude/spanish-pwa-city-app-3oghmr`, деплой на GitHub Pages прошёл.

## Этап 1. Память

Цель этапа: выученное не теряется, нагрузка ровная, грамматика повторяется наравне со словами. В игре это «Поход» и туман забвения над зданиями.

### 1.1 FSRS вместо SM-2 · M

**Нужно до:** 0.3 (желательно, чтобы сразу копить данные).

**Зачем.** FSRS точнее SM-2 предсказывает забывание: при той же доле вспоминаний повторений меньше.

**Решение.** Библиотека `ts-fsrs` (работает офлайн, без обучения параметров на сервере), целевая вероятность вспоминания 0.9, параметры по умолчанию.

**Данные.** `SrsCard` получает `stability`, `difficulty`, `state` и оставляет `due` номером дня, чтобы не переписывать выборки. Версия базы 3 с `upgrade`: у каждой карточки `stability` берётся из `interval` (не меньше 1 дня), `difficulty` из `ef` (линейно: ef 2.5 → 5, ef 1.3 → 9), `state` = review, если `reps > 0`, иначе learning. `due` не трогать: ученик не должен получить лавину повторений в день обновления.

**Оценки.** `wrong` → Again, `almost` → Hard, верно выбором → Good, верно вводом → Good. Easy автоматически не ставится.

**Что меняется.** `src/domain/srs.ts` (новая функция `review` поверх ts-fsrs, старые экспорты сохраняют сигнатуры, где возможно), `src/store/progress.ts`, `src/db/db.ts`, тесты `srs.test.ts` переписать под новые ожидания.

**Проверка.** Тесты: перенос сохраняет `due`, интервал после Good растёт, после Again карточка возвращается завтра, `lapses` считается. В браузере: старый прогресс открывается, «Повторить» показывает то же число карточек, что до обновления.

**Запрос.**

### 2.1 Схема и проверка фраз локаций · M

**Данные.** `src/content/<язык>/phrases/<локация>.json`: `{ location, phrases: [{ id, es, ru, level, alt?, note?, grammar? }] }`. `id` вида `cafe.p.me-pone`, `level` — уровень здания, `grammar` — id урока, правило которого фраза использует. ## Этап 3. Жители

Цель: понятный связный ввод — диалоги и тексты, на 90–95% из уже выученного.

### 3.1 Жители и схема диалогов · M

**Валидатор.** Покрытие: доля слов реплик, которых нет в словаре до этого уровня и нет в `gloss`, не больше 7%. Отчёт о покрытии печатается в `npm run validate`.

## Этап 4. Квесты и испытания

Цель: обучение через задачу и честные проверки вместо покупки прогресса.

### 4.1 Движок квестов · M

**Нужно до:** 3.2.

**Данные.** Квест — граф: узлы с репликой жителя и вариантами ответа героя (`correct`, реакция на неверный ответ, следующий узел). `src/domain/quest.ts`: прохождение, подсчёт верных реплик, режим ответа по номеру попытки (1 — выбор, 2 — сборка из плиток, 3 и дальше — ввод). Тесты на граф и режимы.

### 4.2 Квесты: первые 5 локаций · L

По квесту на уровень здания: 25 квестов на язык. Ситуации коммуникативные: заказать, уточнить, пожаловаться, объяснить.

### 4.3 Испытание здания вместо покупки уровня · M

**Нужно до:** 4.2 (для локаций без квестов остаётся старая схема).

**Правило.** Следующий уровень слов в здании открывается после квеста-испытания этого уровня с 80% верных реплик. Монеты нужны только для первого открытия здания. Улучшение здания за монеты остаётся и влияет на доход и вид здания, но не на доступ к словам.

**Перенос.** Уже купленные уровни остаются открытыми. Экономику (`src/domain/economy.ts`), экран локации и достижения обновить, тесты экономики пересчитать.

**Запрос.**
> Возьми задачу 4.3 из docs/ROADMAP.md. Отдельно проверь на сохранённом прогрессе, что ни один открытый уровень не закрылся.

### 4.4 Испытание района · M

20 смешанных заданий: грамматика района и слова открытых зданий. Порог 75%. Повторная попытка через сутки. Прохождение отмечается на карте грамматики.

### 4.5 Хроника героя · M

Сюжет: по главе на каждое испытание района и на каждые пять испытаний зданий. Экран «Хроника» в профиле. Текст глав на изучаемом языке с переводом по нажатию, уровень текста — уровень района.

## Этап 5. Лист персонажа

Цель: прогресс показывает умение, уровень определяется, а не угадывается.

### 5.1 Входной тест · L

**Как устроен.** 10 минут, адаптивно: слова по уровням зданий и задания по районам грамматики, лестница «верно — сложнее, неверно — проще». Результат — оценка уровня CEFR и набор открытых районов и уровней зданий. Слова, которые ученик показал, становятся карточками с увеличенной стабильностью.

**Когда.** Предлагается при первом запуске курса и доступен в настройках. Можно пропустить.

### 5.2 Навыки героя · M

**Нужно до:** 0.3, 3.2.

Шесть навыков из журнала ответов: Словарь (закреплённые слова), Грамматика (точность по районам), Слух, Чтение, Письмо, Речь (по типам заданий). У каждого ранг A1–B2 по порогам. Профиль: полосы навыков под карточкой уровня. Функции подсчёта в `src/domain/skills.ts` с тестами.

### 5.3 «Я могу…» по CEFR · M

`src/content/<язык>/cando.json`: дескрипторы вроде «Могу заказать еду и попросить счёт» с условием (пройдены квесты такие-то, навык не ниже A2). Свиток в профиле, новые пункты появляются с поздравлением.

### 5.4 Награды за уровни героя · M

Таблица наград в `src/config.ts`: жетоны подсказки (открыть первую букву при вводе; оценка такого ответа не выше Hard), режимы блица, цвета плаща путника на карте. Награды применяются задним числом для уже набранного уровня.

## Этап 6. Голос

### 6.1 Шэдоуинг с записью · M

В сцене и в фразах кнопка «Повторить за жителем»: запись через `MediaRecorder` (работает офлайн), прослушать себя и оригинал подряд. Запись хранится только в памяти. Если доступ к микрофону запрещён, кнопка скрывается с пояснением в настройках.

### 6.2 Минимальные пары · M

Задание «что вы услышали» из двух похожих слов: для испанского r/rr, b/v, ударение (papa/papá), для итальянского двойные согласные (pala/palla), открытое и закрытое e. Контент пар и новое задание в уроках слов.

### 6.3 Ответ голосом · M

В квестах и фразах ответ голосом через `webkitSpeechRecognition` с языком курса, сравнение той же функцией, что и ввод. Только при наличии сети и поддержки, иначе кнопки нет.

## Этап 7. Ритм

### 7.1 План дня на главной · M

Три шага: «Поход», новое (урок, сцена или фраза), квест жителя. Отметки выполненного, выполненный план засчитывается как дневная цель вместо порога XP (настройка).

### 7.2 Напоминания · M

Время напоминания в настройках. `Notification` из service worker через Periodic Background Sync там, где он есть (установленное приложение в Chrome на Android), иначе напоминание не обещать и сказать об этом в настройках.

### 7.3 Праздники · L

Календарь событий обоих языков (Сан-Фермин, Ла Томатина, Феррагосто, Карнавал в Венеции): тематическая неделя со своими 10 словами, сценой, выпуском газеты и украшением города.

## Этап 8. Качество контента

Идёт параллельно всем этапам.

### 8.1 «Сообщить об ошибке» · S

Кнопка в каждом задании и в теории: заметка сохраняется в таблицу `reports` с id задания и текстом, попадает в резервную копию. В настройках «Скопировать отчёты» одним текстом.

### 8.2 Выгрузка контента на вычитку · S

`scripts/export-review.ts`: CSV по языку и типу контента (слово, пример, перевод, id) для носителя.

### 8.3 Загрузка правок носителя · M

`scripts/import-review.ts`: CSV с колонкой исправлений применяется к JSON по id, отчёт об изменённом, валидатор после применения.
