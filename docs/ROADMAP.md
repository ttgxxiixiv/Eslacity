# Дорожная карта Eslacity

Пошаговый план развития для работы через Claude Code. Что строим, описано в `docs/GAME.md`: путешествие героя к Хранилищу Эликсира знания через пять глав (A1–C1), обрывки карты, жители с миссиями и поручениями, медали от дерева до бриллианта, Сфинкс с загадками в финале. К финалу у игрока словарный запас не меньше 3000 слов на изучаемом языке (раздел «Словарный запас» в `GAME.md`). Язык в этой игре — инструмент: каждое игровое действие требует понять или сказать что-то на изучаемом языке.

Правила проекта, команды и порядок выпуска версии описаны в `CLAUDE.md`, Claude Code читает его сам.

## Как работать по этому плану

1. Одна задача — одна сессия Claude Code и одна версия приложения. Если задача не помещается, Claude сам предложит, где её разрезать.
2. Скопируйте в сессию запрос из блока «Запрос» у задачи. Подробности Claude прочитает здесь и в `docs/GAME.md`.
3. Идите по порядку. Зависимости указаны в строке «Нужно до».
4. После выпуска Claude отмечает задачу `[x]` в оглавлении и дописывает журнал в конце файла.
5. Если по ходу решение изменилось (формат данных, числа, названия), Claude правит следующие задачи здесь и `docs/GAME.md`, чтобы документы не расходились с кодом.

### Определение готовности (для каждой задачи)

- Логика в `src/domain/` покрыта тестами, `npm test` проходит.
- `npm run build` проходит: валидатор контента, типы, сборка.
- Сценарий задачи пройден в браузере на обоих языках (после 0.2 — через `npm run e2e`).
- Прогресс со старой версии открывается без потерь, ничего уже открытого не закрывается. Если менялась база, есть тест на перенос.
- Версия поднята, есть запись в `src/content/changelog.ts` и раздел в `docs/STAGES.md`.
- Изменения отправлены в ветку `claude/spanish-pwa-city-app-3oghmr`, деплой на GitHub Pages прошёл.

### Графика

Медали, портреты жителей, карта странствий, Сфинкс и Хранилище требуют рисунков. Порядок для таких задач: Claude делает рабочий вариант, нарисованный кодом (пиксельный SVG или canvas в стиле приложения), и показывает скриншоты. Если вы хотите свой рисунок, пришлите макет, и Claude встроит его, как было с меню и городом.

### 0.2 Сквозные тесты в репозитории · M · сделано в 2.1.1

- `tests/e2e/fixtures.ts`: выбор языка, подмена озвучки, запись карточек и опыта в IndexedDB, ответ на задание по данным из JSON контента.
- `tests/e2e/*.spec.ts` на обоих языках: урок слов целиком (все типы заданий, ввод с типографским апострофом), урок грамматики и «Перечитать теорию», повторение, блиц, переключение языка с сохранением прогресса, офлайн, нижнее меню, поздравление с новым уровнем.
- `package.json`: `"e2e": "npm run build && playwright test"`. Vitest не подхватывает `tests/e2e`.
- `pages.yml`: `npx playwright install --with-deps chromium` и `npm run e2e` перед деплоем.

### 0.4 Частотная сверка и план словаря на 3000 слов · M · сделано в 2.2.1

**Зачем.** К финалу нужно не меньше 3000 слов на язык (сейчас 1159). Чтобы 2070 новых слов на язык были полезными, их выбирают по частотности, а не наугад, и заранее распределяют по главам.

**Что меняется.**
- `scripts/data/freq-<язык>.tsv`: 7000 самых частых лемм языка по субтитрам (FrequencyWords, CC BY-SA 4.0), формы сведены к леммам по lemmatization-lists (ODbL). Строит `scripts/build-freq.ts` из скачанных вручную файлов, в приложение не попадает. Рядом `lemmas-<язык>.tsv`: форма → лемма.
- `scripts/vocab-report.ts` (`npm run vocab`): число слов по главам, уровням мест, CEFR и свиткам; повторы лемм между местами; покрытие первых 1000, 3000 и 5000 частотных слов словами мест и грамматикой. Правила подсчёта — в `scripts/vocab-lib.ts`.
- `src/content/vocabPlan.ts`: плановые числа из `GAME.md`. Валидатор печатает «слов: N из плана 3229» по каждому языку и предупреждает, если в уровне места больше плана (12 слов на уровнях 1–4, 30 на 5–6, 25 на 7).
- `docs/vocab/<язык>.md`: частотные слова, которых нет в курсе, по полосам частоты с подсказкой главы. Список для контентных задач 3.9, 4.8, 4.9, 6.1, 6.5, 7.2 и 7.10. Файл пересобирается `npm run vocab`: взятые слова пропадают сами, вручную его не правят. Место или свиток для слова выбирает контентная задача.

### 7.7 Письмо с образцом · M

Задание без автоматической оценки: житель просит короткое письмо (официальная жалоба в банк, ответ на приглашение), игрок пишет 40–80 слов, затем видит образец и отмечает по чек-листу, что у него есть: обращение, связки, вежливая формула, нужный регистр. Опыт за выполнение, на обрывки и испытания не влияет. Текст игрока хранится локально и виден в профиле как «Дневник писем».

### 7.8 Миссии главы V · L

**Нужно до:** 4.5, 7.2.

20 миссий на язык, пачками по 5 мест. В движке миссий у вариантов ответа героя появляется пометка регистра: неверный регистр не ошибка по смыслу, но житель реагирует (обижается, переспрашивает), и ответ засчитывается как «почти». Характер регистра по жителям: комиссар полиции и банкир только официально, торговка на рынке и бариста по-свойски.

### 7.9 Испытания и Хозяин Эха · M

Испытания мест главы V на выражениях уровня 7. Хозяин Эха — страж района C1: повторяет фразу героя с ошибкой (задания `fix`), просит сменить регистр и перефразировать. Печать V открывает Врата Хранилища, тайная медаль «Выход из Лабиринта».

### 7.10 Свиток главы V: 150 слов · L

150 слов C1 на язык: оттенки чувств и отношения, аргументация и оценка, книжная лексика. Пачками по 50. После задачи `npm run vocab` должен показывать на каждом языке не меньше 3000 уникальных слов и покрытие первых 1000 частотных слов не меньше 90%, 3000 — не меньше 70%. Если не хватает, Claude добавляет задачу на добор с конкретными словами из `docs/vocab/<язык>.md`.

## Этап 8. Хранилище

### 8.1 Банк загадок Сфинкса · L

**Нужно до:** 7.3.

**Данные.** `src/content/<язык>/sphinx.json`, три раунда, по 3 набора в каждом, чтобы повторная попытка шла по другим вопросам:

- Слух: длинный монолог (1–2 минуты озвучки) и спор двух жителей, вопросы на смысл, отношение и намёк.
- Слово: `transform`, `cloze`, `fix`, коллокации и идиомы, материал C1 вперемешку с B2.
- Мудрость: текст 400–600 слов (статья или отрывок прозы), вопросы на понимание и задание `register`: одну мысль сказать официально и по-дружески.

Валидатор: покрытие словарём до уровня 7, единственность ответов, у каждого набора одинаковая сложность по числу заданий каждого вида.

### 8.2 Врата и Сфинкс · L

**Нужно до:** 8.1, 7.9.

Экран Врат на карте странствий, открывается печатью главы V. Сфинкс (спрайт кодом или по вашему макету) загадывает три раунда. Три сердца на всю встречу, раунд пройден при 80%. Если сердца кончились, Сфинкс ждёт три дня, следующий набор другой. Времени на ответ нет. `src/domain/sphinx.ts`: выбор набора, подсчёт, жизни, ожидание, тесты. Реплики Сфинкса на изучаемом языке с переводом по нажатию. Тайная медаль «Взгляд Сфинкса» за первый приход.

**Запрос.**
> Возьми задачу 8.2 из docs/ROADMAP.md. Реплики Сфинкса пиши торжественно и немного загадочно, в официальном регистре.

### 8.3 Эликсир и финал · M

Сцена Хранилища: герой пьёт Эликсир, медальон с глазом над меню становится золотым (новый вариант картинок `nav-*.webp`), титул «Мудрец», тайная медаль «Хранитель пути». Экран финала с итогами пути: дни, слова и выражения, медали, миссии, пять печатей.

### 8.4 Хранитель · M

**Нужно до:** 3.2, 8.3.

Экран Хранилища после финала: сила Эликсира — средняя вероятность вспоминания всех карточек по FSRS. Поручения поддерживают силу. Тридцать дней подряд выше 90% — титул «Хранитель языка». Сила может падать, титулы не отнимаются. Предложение начать второй язык, в его профиле видна медаль «Мудрец» первого.

## Этап 9. Герой

### 9.1 Входной тест · L

10–15 минут, адаптивно (верно — сложнее, неверно — проще): слова по уровням мест и задания по районам, от A1 до C1. Засчитанные главы дают их обрывки и печати, показанные слова становятся карточками с увеличенной стабильностью. Предлагается при первом запуске курса, доступен в настройках, можно пропустить. Врата Хранилища входной тест не открывает: к Сфинксу приходят только через печать главы V.

### 9.2 Награды за уровни героя · M

Таблица в `src/config.ts`: жетоны подсказки (первая буква при вводе, оценка не выше Hard), режимы блица, цвета плаща путника. Выдаются задним числом за уже набранный уровень.

### 9.3 Облик героя и украшения города · M

Плащи и фонари путника за уровни и медали, украшения на карте города (флаги, фонари, клумбы) за золотые медали. Выбор в профиле.

## Этап 10. Голос и ритм

### 10.1 Повторить за жителем · M

В сценах и фразах: запись себя через `MediaRecorder` (работает офлайн), прослушать себя и жителя подряд. Запись только в памяти. Без доступа к микрофону кнопки нет.

### 10.2 Минимальные пары · M

«Что вы услышали» из двух похожих слов: r/rr, b/v, ударение (papa/papá) в испанском, двойные согласные (pala/palla) в итальянском.

### 10.3 Ответ голосом · M

В миссиях и испытаниях ответ голосом через распознавание речи браузера, только при наличии сети и поддержки, иначе кнопки нет.

### 10.4 Напоминания · M

Время напоминания в настройках. Уведомление через Periodic Background Sync там, где он есть (установленное приложение в Chrome на Android); где нет, честно сказать об этом в настройках.

### 10.5 Праздники · L

Сан-Фермин, Ла Томатина, Феррагосто, Карнавал в Венеции: тематическая неделя со своими словами, миссией, украшением города и тайной медалью.

## Этап 11. Качество контента

### 11.1 «Сообщить об ошибке» · S

Кнопка в каждом задании: заметка в таблицу `reports` с id задания, попадает в резервную копию, «Скопировать отчёты» в настройках.

### 11.2 Выгрузка контента на вычитку · S

`scripts/export-review.ts`: CSV по языку и типу контента для носителя.

### 11.3 Загрузка правок носителя · M

`scripts/import-review.ts`: исправления из CSV применяются по id, отчёт об изменённом, валидатор после применения. Выражения C1 и тексты Сфинкса стоит отдать носителю в первую очередь: на этом уровне неестественность заметнее всего.
