# Eslacity

PWA для изучения испанского и итальянского с русского: город из 20 локаций со словами, интервальное повторение, грамматика A1–B2, пиксельная RPG-оболочка. Работает офлайн, сервера нет, весь прогресс хранится на устройстве.

План развития: `docs/ROADMAP.md` (задачи по шагам с готовыми запросами). История версий: `docs/STAGES.md`. Аудиты: `docs/AUDIT.md`.

## Команды

```bash
npm run dev        # локальный сервер Vite
npm test           # vitest, все юнит-тесты
npm run validate   # проверка контента обоих языков (слова, грамматика)
npm run build      # validate + tsc + vite build, результат в dist/
```

Перед любым коммитом должны проходить `npm test` и `npm run build` (сборка включает валидатор и проверку типов).

## Стек

React 19, Vite 8 (rolldown), TypeScript, Tailwind v4, Zustand, Dexie (IndexedDB), vite-plugin-pwa, HashRouter. Тесты: Vitest, для хранилища `fake-indexeddb`.

## Устройство

- `src/lang.ts` — язык курса (`es` | `it`) и его свойства: голоса, артикли, имя базы. Язык читается из `localStorage['eslacity.lang']` при запуске, смена языка перезагружает приложение.
- `src/content/<язык>/words/<локация>.json` — слова (поле `es` исторически означает «форма на изучаемом языке» для любого языка). `src/content/<язык>/grammar/<район>/*.json` — уроки. Схема: `src/content/schema.ts`, валидатор: `src/content/validate.ts` и `scripts/validate-content.ts`.
- `vite.config.ts` строит виртуальный модуль `virtual:grammar-index` (индекс уроков для карты) и режет уроки на чанки по языку и району.
- `src/domain/` — чистая логика без React и базы: проверка ответов (`answer.ts`), SM-2 (`srs.ts`), очередь заданий урока (`lessonQueue.ts`), генераторы заданий, экономика города, стрик, достижения, уровень героя (`heroLevel.ts`). Всё, что можно, пишется здесь и покрывается тестами рядом (`*.test.ts`).
- `src/store/` — Zustand-хранилища. Запись в базу идёт через `persist()` из `src/db/persist.ts`. Загрузка при старте: `src/store/bootstrap.ts`.
- `src/db/db.ts` — Dexie. У каждого языка своя база: `eslacity` (испанский, прежнее имя) и `eslacity-it`. Таблицы: `cards`, `buildings`, `grammar`, `days`, `meta`. Резервная копия: `src/db/backup.ts`.
- `src/screens/` — экраны, `src/components/` — общие компоненты и задания (`components/exercises/`).
- `src/audio/tts.ts` — озвучка через speechSynthesis с выбором голоса языка.
- `src/lib/update.ts` — проверка и установка новой версии (service worker).
- `src/assets/` — картинки города и меню (`nav/nav-es.webp`, `nav/nav-it.webp`).

## Правила

- Язык интерфейса, комментариев, документации и сообщений коммитов — русский. Пишем просто и конкретно.
- Прогресс пользователя нельзя терять. Любое изменение таблиц Dexie — только через новую `this.version(n).stores(...).upgrade(...)` с переносом данных и тестом на перенос. Старые резервные копии должны загружаться. Проверять на обоих языках.
- Новая функция должна работать на обоих языках. Всё, что зависит от языка, берётся из `src/lang.ts` (`L`, `LANG`), а не пишется строкой.
- Приложение работает без сети. Функции, которым нужна сеть (распознавание речи), только дополнительные и не блокируют прохождение.
- Контент проходит `npm run validate` без ошибок и предупреждений. Новые виды контента получают свою проверку в валидаторе.
- Зависимости добавляем, только если без них заметно сложнее (пример допустимой: `ts-fsrs`). Следим за размером сборки: `npm run build` печатает размер precache.
- Стиль: пиксельная RPG, дерево и пергамент (`--color-wood`, `--color-gold` в `src/index.css`). Пиксельный шрифт Tiny5 только для заголовков и подписей, цифры набираются обычным шрифтом. У кнопок без текста есть `aria-label`.
- Не показывать выбранное состояние цветом в нижнем меню: ячейки всегда каменные.

## Выпуск версии

Каждая законченная задача — отдельная версия:

1. Поднять `version` в `package.json` (новая функция — минорная, исправление — патч).
2. Добавить запись сверху в `src/content/changelog.ts`. Версия первой записи должна совпадать с `package.json`, это проверяет тест.
3. Дописать раздел в `docs/STAGES.md`: что сделано, как устроено, что проверено.
4. `npm test`, `npm run build`, проверка в браузере (ниже).
5. Коммит и push в ветку `claude/spanish-pwa-city-app-3oghmr`. Push в эту ветку запускает `.github/workflows/pages.yml`: тесты, сборка и деплой на https://ttgxxiixiv.github.io/Eslacity/.

## Проверка в браузере

Chromium установлен в `/opt/pw-browsers`, Playwright настроен (не запускать `playwright install`). Порядок: `npm run build`, отдать `dist/` статическим сервером (`python3 -m http.server` из папки с копией `dist`), пройти сценарий скриптом Playwright на ширине телефона (393×852, `isMobile`, `hasTouch`). Язык переключается записью `localStorage['eslacity.lang']` и перезагрузкой. Озвучку в тестах подменять: `speechSynthesis.speak = () => {}` через `addInitScript`.

После задачи 0.2 из `docs/ROADMAP.md` сценарии лежат в `tests/e2e` и запускаются через `npm run e2e`.
