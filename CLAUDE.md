# Eslacity

PWA для изучения испанского и итальянского с русского: город из 20 локаций со словами, интервальное повторение, грамматика A1–C1, пиксельная RPG-оболочка. Работает офлайн, сервера нет, весь прогресс хранится на устройстве.

Игровой замысел: `docs/GAME.md` (путь к Хранилищу, главы, обрывки карты, жители, медали, Сфинкс). План развития: `docs/ROADMAP.md` (задачи по шагам с готовыми запросами). История версий: `docs/STAGES.md`. Аудиты: `docs/AUDIT.md`.

## Команды

```bash
npm run dev        # локальный сервер Vite
npm test           # vitest, все юнит-тесты
npm run validate   # проверка контента обоих языков (слова, грамматика)
npm run vocab      # отчёт о словаре: покрытие частотного списка, docs/vocab/<язык>.md
npm run build      # validate + tsc + vite build, результат в dist/
```

Перед любым коммитом должны проходить `npm test` и `npm run build` (сборка включает валидатор и проверку типов).

## Стек

React 19, Vite 8 (rolldown), TypeScript, Tailwind v4, Zustand, Dexie (IndexedDB), vite-plugin-pwa, HashRouter. Тесты: Vitest, для хранилища `fake-indexeddb`.

## Устройство

- `src/lang.ts` — язык курса (`es` | `it`) и его свойства: голоса, артикли, имя базы. Язык читается из `localStorage['eslacity.lang']` при запуске, смена языка перезагружает приложение.
- `src/content/<язык>/words/<локация>.json` — слова (поле `es` исторически означает «форма на изучаемом языке» для любого языка). `src/content/<язык>/grammar/<район>/*.json` — уроки. У каждого упражнения постоянный `id` вида `<lessonId>.<n>`: новым упражнениям его проставляет `npx tsx scripts/add-exercise-ids.ts`, существующие id не менять. `src/content/<язык>/npcs.json` — жители мест (по одному на место, свои в каждом языке, `src/content/npcs.ts`), портрет рисуется кодом из поля `look` (`src/components/npcArt.ts`), а если в `look` есть `portrait` — рисованной картинкой `src/assets/portraits/<язык>/<portrait>.webp` (`NpcPortrait`, `portraitUrl`; на картах города и странствий всегда пиксельная фигурка, `pixel`). Портреты обоих языков режет `scripts/cut-portraits.py` из `docs/design/portraits-<язык>.jpg` (координаты рамок у каждого листа свои, промт итальянского листа — `docs/design/portraits-it-prompt.md`), наличие картинки проверяет `validatePortraits`. `src/content/<язык>/scrolls/<глава>.json` — свитки земель, общие слова главы без места (id `scroll1.<slug>`, грузятся как «место» `scroll1`, в индексе `SCROLL_WORDS`). `src/content/<язык>/chronicler.json` — Летописец, житель без места: просит учить слова свитка на карте странствий, его поручения — слова свитков (`npcFor`, `SCROLL_PLACE`). `src/content/<язык>/phrases/<место>.json` — готовые фразы ситуации для миссий: id `ph:<место>.<slug>`, необязательные слова в скобках (`src/domain/phrase.ts`), в словарный запас не входят; валидатор проверяет, что слова фразы есть в словаре мест того же уровня или ниже (леммы из `scripts/data`, `uncoveredWords` в `scripts/vocab-lib.ts`). Схема: `src/content/schema.ts`, валидатор: `src/content/validate.ts` и `scripts/validate-content.ts`.
- Виды упражнений грамматики (все пять базовых есть в каждом уроке, это требует валидатор): `choose`, `gap`, `truefalse` и продуктивные `build` (собрать предложение из плиток, лишние в `extra`, другой порядок в `alt`) и `type` (вписать форму в `___`, `hint`, `alt`). Проверка — `checkGrammar` в `src/domain/grammar.ts` (форма без ударения — «почти», опечатки не прощаются: `checkForm`), показ — `GrammarItemView` в `src/components/exercises/GrammarItem.tsx`, общий для урока, повторения правил и стражей. Лишняя плитка не должна собирать другую верную фразу, у ввода подсказка снимает второй ответ, равноправные формы — в `alt`; `src/content/grammarProductive.test.ts` проверяет это на всём контенте, `tests/e2e/grammar.spec.ts` проходит каждый урок целиком. Виды уровня C1 (задача 7.3, необязательные): `transform` (пересказ с ключевым словом `keyword`), `cloze` (текст с пропусками, у каждого свой список `answers`), `fix` (найти слово `wrong` и вписать форму), `register` (та же мысль в регистре `to`: выбор `options` или плитки `extra`), `combine` (связать две фразы связкой `connector`), `paraphrase` (выбор того же смысла). Проверка — там же в `checkGrammar`, ввод без букв ответа в испытаниях (`TYPED_KINDS`), валидатор — `checkC1Exercise`. Сквозной `answerGrammar` находит задание по `data-ex`. Район C1 (глава V, задачи 7.4–7.5): 20 уроков `src/content/<язык>/grammar/c1/`, в каждом не меньше трёх видов C1; страж главы V — Хозяин Эха.
- План словаря: `src/content/vocabPlan.ts` (числа из `docs/GAME.md`). Частотные списки лемм лежат в `scripts/data/` (строит `scripts/build-freq.ts`, источники и лицензии в шапке файлов), в сборку не попадают. После добавления слов запускать `npm run vocab`, он пересобирает `docs/vocab/<язык>.md`.
- `vite.config.ts` строит виртуальные модули `virtual:grammar-index` (индекс уроков для карты) и `virtual:word-index` (id слов по местам и уровням для пути, `src/content/wordIndex.ts`) и режет уроки на чанки по языку и району.
- Путь: `src/store/journey.ts` хранит полученные обрывки и печати в `meta.journey` и выдаёт новые через `sync()` (при запуске и в конце урока, вместе с медалями — `syncAndEvaluate`). Полученное не отнимается. Там же открытая глава (`opened`): уровни слов и районы грамматики следующих глав закрыты (`isLevelOpen`, `isDistrictOpen` в `chapters.ts`), глава открывается, когда собрана карта предыдущей. Титул героя (`heroTitle`, хук `useHeroTitle`) зависит от собранных подряд карт, сцена перехода `ChapterScene` показывается один раз на главу (`celebrated`).
- Уровни слов места: 1–5 открывает здание (`MAX_BUILDING_LEVEL`), уровень 6 (B2, глава IV) — без улучшения, у здания 5-го уровня после выученного уровня 5 (`isWordLevelOpen`, `wordLevelCap` в `src/domain/levels.ts`, их берут `next.ts` и `Location.tsx`). Валидатор требует CEFR главы с уровня 5: 5 — B1, 6 — B2. Уровень 7 (C1, глава V): 25 слов и до 15 устойчивых выражений на место. Выражение — запись слова с полем `kind` (`collocation`, `idiom`, `formula`, `false-friend`), обязательным `register`, у идиомы `literal`, у ложного друга `note`, `pair` — взаимная ссылка на выражение в другом регистре (`checkExpression`, `checkPairs` в `validate.ts`). Метки регистра и вида — `wordTags` в `src/domain/expression.ts`, компонент `WordTags`; в цель 3000 слов выражения не входят. Одинаковый перевод у слов разных мест и свитков одного языка — предупреждение (`validateTranslations`): в задании «Как сказать» было бы два верных ответа.
- `src/domain/` — чистая логика без React и базы: проверка ответов (`answer.ts`), интервальное повторение FSRS через `ts-fsrs` (`srs.ts`: стабильность, сложность, `retrievability`), очередь заданий урока (`lessonQueue.ts`), генераторы заданий, экономика города, стрик, медали (`medals.ts`), уровень героя (`heroLevel.ts`), главы и обрывки карты (`chapters.ts`), словарный запас (`vocabulary.ts`). Всё, что можно, пишется здесь и покрывается тестами рядом (`*.test.ts`).
- `src/store/` — Zustand-хранилища. Запись в базу идёт через `persist()` из `src/db/persist.ts`. Загрузка при старте: `src/store/bootstrap.ts`.
- Поручения жителей: `src/domain/errands.ts` (план на день, сборка из карточек места, у Летописца — из слов свитков, формулировки из `npcs.json` поля `errands`), хранилище `src/store/errands.ts` (`meta.errands`: план, выполненные, очки репутации). Поручение проходится через `ReviewRun` из `src/screens/Review.tsx`. С главы V одно поручение в день — «Эхо» (`kind: 'echo'`, `ECHO_CHAPTER`): карточки — выражения места с парой (`EXPRESSION_PAIRS` из `virtual:word-index`), задания `register` собирает `echoExercise` (`src/domain/echo.ts`: выбор, с интервала 3 дня — плитки), проходятся фазой «Эхо» в `ReviewRun` через `RuleReview`; верные ответы копит `meta.errands.echo` для линии медалей «Эхо». В обычных поручениях выражения C1, которые уже не новые, идут на ввод (`typeExpressions`).
- Карточки в `cards` четырёх видов: слова (`cafe.te`), правила — упражнения грамматики (`g:a1.02-ser.3`), фразы мест (`ph:cafe.un-cafe`, id как у фразы) и формы глаголов кузницы (`v:hablar.presente.3`). Всё, что считает или ищет слова, берёт только карточки слов через `src/domain/itemId.ts` (`splitCards`, `wordIds`, `isWordId`, `isRuleId`, `isPhraseId`, `isVerbId`).
- Фразы в игре: урок «Как здесь говорят» в месте (`/phrases/:место/:уровень`, `src/screens/PhraseLesson.tsx`), задания и прохождение — `src/components/PhraseRun.tsx` и `src/domain/phraseSteps.ts`, проверка ввода — `checkPhrase` в `answer.ts`, загрузка — `src/content/phrases.ts`. В повторении фразы идут после слов, в поручениях — вместе со словами места.
- Сцены: `src/content/<язык>/scenes/<место>.json` (`{ location, scenes }`, сцена `sc:<место>.<глава>`: житель, реплики `who/es/ru`, вопросы на понимание, `gloss` — перевод слов не из словаря). Валидатор (`validateScenes`): незнакомых слов к уровню главы не больше 7%, каждое переведено в `gloss`; `npm run validate` печатает долю незнакомых. Переводы остальных слов для нажатия достраивает при сборке плагин `scene-gloss` в `vite.config.ts` (`glossIndex` из `scripts/vocab-lib.ts`, поле `auto`). Экран `/scene/:id` (`src/screens/Scene.tsx`), вход — «Разговор» в месте.
- Шёпоты (глава IV): в том же файле сцен места, id `wh:<место>.4`, `mode: 'overhear'`. Говорят житель места (`npc`) и другой житель (`who` — его id, `speakerOf` в `src/content/npcs.ts`), у них разная высота голоса, герой молчит. Вопросы `kind: 'stance'`: кто с чем согласен, чем недоволен, что имел в виду. Проверка — `overhearIssues` в `validateScenes`. Экран тот же `/scene/:id` (`Whisper` в `Scene.tsx`): реплики только голосом, текст скрыт до вопросов (без звука виден), потом расшифровка; ответы в журнале — `listen-whisper`. Вход — «Шёпот» в месте с главы IV, сквозной тест `whispers.spec.ts` проходит все шёпоты контента.
- Сюжетные миссии: `src/content/<язык>/missions/<место>.json` (`ms:<место>.<глава>`: житель, сцена-вступление, граф `nodes` из реплик `say` и ответов героя `answer` с ветками-фразами места и реакцией `wrong`). Логика — `src/domain/mission.ts` (ответ, варианты, режим по номеру прохождения: выбор, плитки, ввод; засчитана при 80%), валидатор — `validateMissions` (граф, фразы своего места и уровней главы, не меньше 5 ответов, 7% незнакомых слов). Прохождения — `meta.missions` (`src/store/missions.ts`). Экран `/mission/:id` (`src/screens/Mission.tsx`). Условие обрывка `mission` включено: если у места есть миссия главы, обрывок ждёт её (`JourneyInput.missions` из `virtual:word-index`, `MISSION_CHAPTERS`). Миссия главы I открыта сразу, следующих глав — с отношений «Приятель» (`missionOpen`). С главы V в каждой миссии есть узел тона: ответ с `register` (какого тона ждёт житель) и репликой `tone`, ветки — фразы с `register`, первая в нужном тоне; чужой тон — «почти» (`offTone`, `isRegisterNode`, `REGISTER_FROM_CHAPTER` в `mission.ts`), житель реагирует, над ответом метка «Тон: …»; постоянный тон жителя — `register` в `npcs.json` (банкир и комиссар официально, торговка и бариста по-свойски), проверка `toneIssues` в валидаторе, сквозной тест `tones.spec.ts`. С главы IV в каждой миссии есть спор: ответ с тремя ветками `move` (`object`, `concede`, `compromise`), все верные, у каждой своя реакция; в плитках и вводе герой сначала выбирает ход (`withMove`, `isDispute`, `MOVE_LABEL` в `mission.ts`), валидатор требует спор с главы IV (`DISPUTE_FROM_CHAPTER`), сквозной тест — `disputes.spec.ts`. У места по сцене и миссии на главу в одном файле (`sc:<место>.<глава>`, `ms:<место>.<глава>`). Сквозные тесты сами проходят все сцены и миссии из контента (`scenes.spec.ts`, `missions.spec.ts`). Слова сюжета: Хранилище — `la Bóveda` / `il Caveau`, обрывок — `trozo` / `pezzo`.
- Испытания мест: `src/domain/trial.ts` (задания, порог 80%, повтор через сутки, id `tr:<место>.<глава>`), хранилище `src/store/trials.ts` (`meta.trials`), экран `/trial/:id` (`src/screens/Trial.tsx`), вход — «Испытание» в месте. Условие обрывка `trial` включено (`JourneyInput.isTrialDone`), счётчик линии «Испытатель». Ввод в испытании без букв ответа (`exam` у `TypeAnswer` и `PhraseType`, `EXAM_KEYS`). Сквозные тесты засевают пройденные испытания через `seedTrialsDone`. С главы V (`EXPRESSION_TRIAL_CHAPTER`) в испытании пять выражений места, два из них — задания «Эха» (`echoExercise`, в журнал на карточку выражения через `cardId`).
- Стражи земель: `src/content/<язык>/guardians.json` (глава, имя, роль, реплики `greeting`/`win`/`lose`, голос, портрет; `GUARDIANS`, `guardianOf` в `src/content/npcs.ts`, проверка `validateGuardians`: страж у каждой главы с уроками). Логика — `src/domain/guardian.ts` (20 заданий: грамматика района, слова главы, свиток; порог 75%, сутки). Страж с `listen: true` (Хранительница леса, глава IV, обязательно по `LISTEN_GUARDIAN_CHAPTERS`) даёт слова только на слух; без звука — текстом. `GUARDIAN_KINDS` — обязательные виды заданий стража: у Хозяина Эха (глава V) не меньше двух `fix`, `register`, `paraphrase`; его победа даёт тайную медаль «Выход из Лабиринта» (`seals` в `MedalCounters`). Прохождения лежат в `meta.trials` под id `gd:<глава>` (считаются в «Испытателе»). Печать ждёт стража (`JourneyInput.isGuardianDone`, условие `guardian` вместо прежнего «все уроки района»). Экран `/guardian/:глава` (`src/screens/Guardian.tsx`), вход — страж у печати и панель под картой странствий. Испытания места и стража проходятся общим `TrialPlayer` (`src/components/TrialPlayer.tsx`), в сквозных тестах — `playTrial`.
- Кузница глаголов: `src/content/<язык>/verbs.json` (кузнец и 60 глаголов, у неправильных только отличия от правил: `forms`, `yo`, `fut`, `pp`, `ch`, `isc`, `aux`), генератор форм и задания — `src/domain/verbs.ts` (`conjugate`, `forgeTasks`, `openTenses`: время открывает его урок, `TENSE_LESSON`), загрузка — `src/content/verbs.ts`, валидатор `validateVerbs` (запись, совпадающая с генератором, — ошибка). Экран `/forge` (`src/screens/Forge.tsx`), вход — карточка на экране грамматики. Ошибки — карточки `v:<глагол>.<время>.<лицо>` (`isVerbId`), они повторяются только в кузнице: `splitCards` кладёт их в `verbs`, в слова, повторение и поручения они не входят. Журнал ответов — режим `forge`.
- Сфинкс (задача 8.1): `src/content/<язык>/sphinx.json` — раунды по три набора (повторная попытка идёт по другому). Загадка слова `word`: наборы `sx:word.<n>`, в каждом одинаковый состав заданий с вводом (`SPHINX_WORD_MIX`: 3 `transform`, 2 `cloze`, 3 `fix`, 2 `type` на коллокации и идиомы), задания — обычные упражнения грамматики с id `sx:word.<n>.<k>`. Валидатор `validateSphinx` (проверка упражнения общая с уроками — `checkExercise`, повтор задания между наборами — ошибка, незнакомых слов к уровню 7 не больше 7%), загрузка `src/content/sphinx.ts`, тест контента `src/content/sphinx.test.ts` (каждый ответ и `alt` проходят `checkGrammar`). Загадка слуха `hear`: наборы `sx:hear.<n>` — монолог одного жителя или Летописца (`cronista`, 150–260 слов) и спор двух жителей с разной высотой голоса (не меньше 8 реплик), 8 вопросов с видом `gist`/`stance`/`hint` и частью `monologue`/`dispute` в одинаковом составе (`SPHINX_HEAR_MIX`), незнакомые слова — в `gloss` (`hearIssues`, голоса проверяются по `npcs.json` и `chronicler.json`). Загадка мудрости `wisdom`: наборы `sx:wisdom.<n>` — заголовок и текст 400–600 слов абзацами с переводом, 5 вопросов на понимание, два задания `register` с плитками (одно `formal`, другое `informal`, id `sx:wisdom.<n>.<k>`), незнакомые слова в `gloss` (`wisdomIssues`). Общие проверки раундов: `glossIssues`, `coverageIssues`, `optionIssues`. Реплики Сфинкса — раздел `sphinx` (имя, голос, `speech` по `SPHINX_LINES`, `gloss`; проверка `speakerIssues`).
- Врата и Сфинкс (задача 8.2): логика `src/domain/sphinx.ts` (раунды по порядку `SPHINX_ROUNDS`: слух, слово, мудрость; три сердца на встречу, порог 80%, провал стоит сердце, набор — `setIndex` по числу попыток, без сердец ожидание `SPHINX_WAIT_MS` три дня, `arrive` возвращает сердца после ожидания и отмечает первый приход; задания раунда — `sphinxItems`), хранилище `meta.sphinx` (`src/store/sphinx.ts`). Экран `/sphinx` (`src/screens/Sphinx.tsx`, спрайт кодом `SphinxArt`), вход — панель Врат на карте странствий с печатью главы V (`GATES_CHAPTER`). Задания идут через `TrialPlayer` (вопросы на понимание — `TrialItem` вида `question`, журнал — режим `sphinx`); в загадке слуха реплики только голосом (без звука — текстом), текст мудрости можно перечитать кнопкой «Текст». ## Правила

- Игра на первом месте: язык — инструмент для игровых действий. Новая учебная механика оформляется как часть мира (поручение, миссия, испытание), см. `docs/GAME.md`.
- Язык интерфейса, комментариев, документации и сообщений коммитов — русский. Пишем просто и конкретно.
- Прогресс пользователя нельзя терять. Любое изменение таблиц Dexie — только через новую `this.version(n).stores(...).upgrade(...)` с переносом данных и тестом на перенос. Старые резервные копии должны загружаться. Проверять на обоих языках.
- Новая функция должна работать на обоих языках. Всё, что зависит от языка, берётся из `src/lang.ts` (`L`, `LANG`), а не пишется строкой.
- Приложение работает без сети. Функции, которым нужна сеть (распознавание речи), только дополнительные и не блокируют прохождение.
- Контент проходит `npm run validate` без ошибок и предупреждений. Новые виды контента получают свою проверку в валидаторе.
- Зависимости добавляем, только если без них заметно сложнее (пример допустимой: `ts-fsrs`). Следим за размером сборки: `npm run build` печатает размер precache.
- Стиль: пиксельная RPG, дерево и пергамент (`--color-wood`, `--color-gold` в `src/index.css`). Пиксельный шрифт Tiny5 только для заголовков и подписей, цифры набираются обычным шрифтом. Кириллица Tiny5 подключена из `src/assets/fonts` с исправленными Ь, Ъ, Ы (`scripts/patch-tiny5.py`, лицензия OFL рядом). У кнопок без текста есть `aria-label`.
- Главная сделана по макету `docs/design/home-mockup.jpg` (с 2.57.0): рамы, свитки и плашки — картинки из макета в `src/assets/home` (их режет `scripts/build-home-art.py`: стирает текст, делает прозрачный фон). Плашки тянутся по ширине через `border-image` (края не искажаются), под ним та же картинка фоном, чтобы не было швов. Надписи главной — Fira Sans Condensed (`home-font`). Огонёк стрика в макете серый, горящий — `flame-lit.webp` (строит `scripts/build-flame-lit.py`). Цель дня справа в панели — «Дневной переход» (`DailyRoad`, доли пути и придорожные фонари — `roadState` в `src/domain/dailyRoad.ts`; фонари режутся из `docs/design/road-posts.png`): дорога тянется через `border-image` (`.road-bar`), пройденная часть обрезается `clip-path`, картинки режет `scripts/build-road-art.py` из `docs/design/daily-road.png` (пурпурный фон снимается по «пурпурности» пикселя). Окно портрета на свитке квеста задано долями высоты карточки (`QuestWindow`): свиток тянется по высоте. Накидки путника — `road-walker-<материал>.webp` (тот же скрипт режет их из `docs/design/cloaks.png`, промт листа — `docs/design/cloaks-prompt.md`; ширина у накидок разная, на экране задаётся только высота), карта картинок — `WALKER` в `src/components/walkerArt.ts`. Тёмный фон — класс `home-dark` на `body`, пока открыт экран. Остальные экраны на светлом пергаменте.
- Не показывать выбранное состояние цветом в нижнем меню: ячейки всегда каменные.

## Выпуск версии

Каждая законченная задача — отдельная версия:

1. Поднять `version` в `package.json` (новая функция — минорная, исправление — патч).
2. Добавить запись сверху в `src/content/changelog.ts`. Версия первой записи должна совпадать с `package.json`, это проверяет тест.
3. Дописать раздел в `docs/STAGES.md`: что сделано, как устроено, что проверено.
4. `npm test`, `npm run build`, проверка в браузере (ниже).
5. Коммит и push в ветку `claude/spanish-pwa-city-app-3oghmr`. Push в эту ветку запускает `.github/workflows/pages.yml`: тесты, сборка и деплой на https://ttgxxiixiv.github.io/Eslacity/.

## Проверка в браузере

Сквозные тесты лежат в `tests/e2e` (Playwright) и запускаются командой `npm run e2e`: она собирает приложение, поднимает `vite preview` и проходит сценарии на обоих языках на экране телефона 393×852. Chromium уже установлен в `/opt/pw-browsers`, `@playwright/test` закреплён на версии 1.56.1 под этот браузер (не запускать `playwright install` и не менять версию без нужды). В CI тесты идут перед деплоем.

- `tests/e2e/fixtures.ts`: `openApp` (язык и подмена озвучки), `seedDueCards`, `seedXp`, `playWords` (проходит урок слов или повторение, отвечая по данным контента), `answerGrammar` (правильный ответ в уроке грамматики по JSON урока).
- Новая функция получает свой сценарий в `tests/e2e/*.spec.ts` для обоих языков.
- Для разовой проверки или скриншотов удобно писать отдельный скрипт Playwright в папке сессии, не в репозитории.
- После изменения логики проверки ответов стоит убедиться, что тест ловит поломку: временно сломать проверку, увидеть падение, вернуть.
